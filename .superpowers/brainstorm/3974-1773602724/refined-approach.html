Extract from terminar

terminar-core (library crate)

The PTY session engine — extracted from server/src/

What moves into the library:
  • session.rs — session state machine, lifecycle
  • pty.rs — PTY spawning (portable-pty)
  • history.rs — output history buffer (zstd)
  • persistence.rs — session state persistence
  • handlers/ — message handlers (session, I/O)
  • lib.rs — HTTP/WebSocket routing, message dispatch
What stays in terminar-server binary:
  • main.rs — CLI args, socket path, startup
  • auth.rs / jwt.rs — terminar-specific auth
  • tls.rs — TLS setup
  • audit.rs — audit logging

Key question: scope of the library extraction

How much of terminar-server should become the library?

A

Minimal core (PTY + sessions only)

Just the PTY engine and session management. Agent runner builds its own HTTP/WebSocket layer. ~5 files extracted.

B

Full server as library (recommended)

PTY + sessions + HTTP/WebSocket routing + message dispatch. Agent runner calls TerminarServer::new().start() and extends the message handler. ~10 files extracted.

C

Trait-based plugin system

Core server with trait MessageHandler that consumers implement. Most flexible, most work upfront.
